Factory Inventory Management System

System architecture, technology stack, and data flow

1. Overview

A full-stack demo for factory operations: inventory tracking across warehouses, order management, demand forecasting, backlog monitoring, spending analytics, and reporting. The application is a single-page Vue frontend that talks to a FastAPI backend over JSON. All data is held in memory and loaded from JSON files at backend startup; there is no database.

5. Data Flow

1. User actionChanges a filter (time period, warehouse, category, status) or opens a detail modal.
2. ComposableuseFilters.js updates reactive filter refs.
3. API clientapi.js builds query params, skipping values set to all.
4. FastAPIRoute applies filters to in-memory lists and validates the result with Pydantic.
5. Vue renderRaw data sits in refs; computed properties derive totals and charts for display.

6. Filtering Model

Filters

  • Time period: month (YYYY-MM) or quarter (Q1-2025 to Q4-2025)
  • Warehouse and category: apply to inventory, orders, and dashboard
  • Order status: applies to orders and dashboard

Behavior

  • Filters are optional query params. A value of all or an absent param skips that filter.
  • Matching is case-insensitive for category.
  • Inventory has no time dimension, so it ignores the month filter.
  • Filtering copies data and never mutates the loaded lists.

8. Security and Deployment Notes

This is a development demo. It has no authentication or authorization; the user profile shown in the UI is hard-coded in client/src/composables/useAuth.js. CORS allows all origins, and the API base URL is hard-coded to localhost:8001. The backend binds to 127.0.0.1 by default. Set HOST only when network access is intended. Before any production use, add authentication, restrict CORS origins, and move the API URL to configuration.
